## Context

目前 `burst` 指令只要求數量、SMTP host 與 port。`cmd/burst_cmd.go` 會讀取未綁定的 `burst-domain`，`sendmail.BurstModeSendMail` 則先用該網域清單建立 100 個隨機地址，再從同一池分別抽取 From 與 To。呼叫端無法固定任一地址，也沒有在併發開始前驗證網域是否適合大量寄信。

這項變更同時跨越 Cobra/Viper 參數解析與 `sendmail` 的併發發送邏輯。安全檢查必須位於可程式化測試的業務邏輯層，CLI 僅負責收集參數與呈現錯誤，避免其他呼叫端繞過保護。

## Goals / Non-Goals

**Goals:**

- 支援 From 與 To 各自固定或隨機的四種組合。
- 讓隨機地址的網域來源完全明確，不使用隱含預設值。
- 僅自動信任正向表列的 `rd01.softnext.com.tw`，並以逐網域參數授權其他網域。
- 在任何 goroutine 或 SMTP 呼叫產生前完成全部驗證，確保錯誤時零封信送出。
- 保持既有 burst 的併發、隨機主旨、隨機內容與多網域抽選能力。
- 讓地址解析、授權及選擇規則能以純單元測試驗證。

**Non-Goals:**

- 不判斷 SMTP host 是開發、QC 或產品環境，也不自動查詢 DNS/MX。
- 不新增互動式確認、寄信速率限制、SMTP 認證或重試機制。
- 不擴充 Cc/Bcc、每封多收件人或從檔案匯入地址。
- 不改變 TUI、一般 compose、主旨與內容的產生規則。
- 不建立可由設定檔永久擴充的安全網域清單；本次額外授權僅限單次 CLI 呼叫。

## Decisions

### 1. 以具名選項模型取代持續擴張的位置參數

新增 burst 選項模型，包含 quantity、host、port、固定 From、固定 To、隨機 domains 與本次 allowed domains。`BurstModeSendMail` 接收此模型並回傳 `error`，CLI 改用 Cobra `RunE` 傳遞驗證或發送錯誤。

這比繼續增加位置參數更能表達固定／隨機組合，也能集中安全驗證。替代方案是在 `cmd` 層先驗證後呼叫舊函數，但那會使其他 Go 呼叫端仍可繞過網域保護，因此不採用。

### 2. 先解析成不可變的發送計畫，再開始併發

發送流程分成兩階段：

1. 預先驗證並解析選項，產生已確認可用的固定地址或隨機網域池。
2. 驗證成功後才建立地址池、goroutine 並呼叫 SMTP。

固定 `--from`、`--to` 各只接受一個完整 mailbox address；若欄位空白，對應地址在每封郵件中從 `--domain` 清單隨機產生。固定值同時用於 MIME header 與 SMTP envelope，避免顯示地址與實際投遞地址不一致。

將預先驗證與副作用建立明確邊界，可用假的 `SendMail` 驗證任何錯誤皆為零次呼叫。替代方案是在每個 goroutine 內驗證，可能在其中一個錯誤被發現前已寄出部分郵件，因此不採用。

### 3. 隨機模式沒有預設網域

只要 From 或 To 任一欄未指定，就必須提供至少一個有效 `--domain`。同一網域池供所有未指定欄位使用，保留既有逗號分隔多網域並隨機抽選的概念。From 與 To 都固定時不要求 `--domain`。

不將 SMTP host 推導為郵件網域，因為連線主機名稱、IP 與實際收件網域沒有可靠的一對一關係；也不內建 `rd01.softnext.com.tw` 作為隨機預設，以維持使用者的明確意圖。

### 4. 採精確網域正向表列與逐網域授權

內建安全網域集合初始只有 `rd01.softnext.com.tw`。系統收集本次實際使用的所有網域，包括：

- `--domain` 中供隨機地址使用的網域；
- 固定 `--from` 的實際 mailbox domain；
- 固定 `--to` 的實際 mailbox domain。

網域在比較前去除周邊空白並轉為小寫；授權採精確相等，不因父網域安全而自動信任子網域。每個不在內建表列的網域都必須精確出現在可重複的 `--allow-domain` 中。所有 domain 與 allow-domain 值本身也必須先通過格式驗證。

選擇逐網域的 `--allow-domain`，而不是布林 `--force` 或已知危險網域 denylist：前者將授權限縮到使用者明確寫出的值，後者無法完整列舉正式與公開網域。

### 5. 安全驗證涵蓋固定地址

即使使用者明確提供 `--from` 或 `--to`，其網域仍套用相同表列規則。例如固定寄往 Gmail 仍需 `--allow-domain gmail.com`。這讓 burst 的大量發信保護一致，不會因固定地址路徑而繞過安全邊界。

### 6. 保留既有隨機與併發語意

未指定的 From/To 仍按每封郵件從預先建立的隨機地址池抽取；固定值則在整批郵件中維持不變。主旨、內容與工作分配方式不因本次變更而改動。這將安全功能限制在地址控制與驗證，降低非必要回歸。

## Risks / Trade-offs

- [Risk] 既有只傳 quantity/host/port 的腳本會失敗 → 在錯誤訊息與 README 明確提示補上 `--domain`，並將此行為列為 breaking change。
- [Risk] 使用者誤以為授權父網域也包含子網域 → 採精確比對，錯誤訊息列出每個未授權的實際網域。
- [Risk] 大小寫或逗號周邊空白造成意外拒絕 → 比較前統一 trim 與小寫，但不對 mailbox local part 做正規化。
- [Risk] `--allow-domain` 仍可被刻意用於正式網域 → 這是明確的單次授權；工具無法可靠判斷所有產品網域，文件需醒目說明風險。
- [Risk] 函數改為回傳 error 會影響既有 Go 呼叫端與測試 → 專案內同步遷移所有呼叫點，並以編譯與全套測試確認。

## Migration Plan

1. 先以單元測試定義地址組合、網域表列、明確授權與零寄送副作用。
2. 新增 burst 選項模型與預先驗證，讓發送函數回傳 error。
3. 新增並綁定 CLI flags，將命令改為 `RunE`。
4. 更新既有測試呼叫與 README 範例；執行格式化、靜態檢查與全套測試。
5. 若需回復，還原 CLI flags 與函數簽名即可；此變更沒有資料或外部狀態 migration。
